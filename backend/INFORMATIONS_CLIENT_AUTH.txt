1. CRÉATION D'UN CLIENT
================================================================================

Endpoint: POST /api/clients
Headers: Content-Type: application/json

CORPS DE LA REQUÊTE (JSON):
{
  "first_name": "Jean",
  "last_name": "Dupont",
  "email": "jean.dupont@example.com",
  "password": "MotDePasse123!",
  "birth_date": "1990-05-15",
  "gender": "M",
  "address": "123 Rue de la Paix, Paris",
  "phone_number": "+33612345678",
  "nationality": "Française"
}

CHAMPS OBLIGATOIRES:
- first_name    : Prénom
- last_name     : Nom
- email         : Email (unique)
- password      : Mot de passe (sera encodé en BCrypt)
- birth_date    : Date de naissance (format YYYY-MM-DD)
- gender        : Genre (M ou F)
- address       : Adresse complète
- phone_number  : Numéro de téléphone
- nationality   : Nationalité

RÉPONSES:
✅ 201 Created : Client créé avec succès
   Retourne toutes les informations SAUF le password

❌ 409 Conflict : Email déjà utilisé

❌ 400 Bad Request : Données manquantes ou invalides

2. CONNEXION CLIENT (LOGIN)
================================================================================

Endpoint: POST /api/client/auth/login
Headers: Content-Type: application/json

CORPS DE LA REQUÊTE:
{
  "email": "jean.dupont@example.com",
  "password": "MotDePasse123!"
}

RÉPONSE SUCCÈS (200 OK):
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "token_type": "Bearer",
  "expires_in": 86400,
  "user_id": 1,
  "email": "jean.dupont@example.com",
  "first_name": "Jean",
  "last_name": "Dupont",
  "message": "Connexion réussie"
}

INFORMATIONS DU TOKEN:
- access_token : Token JWT à utiliser dans les prochaines requêtes
- token_type   : Toujours "Bearer"
- expires_in   : Durée de validité en secondes (86400 = 24h)
- user_id      : ID du client
- email        : Email du client
- first_name   : Prénom
- last_name    : Nom

RÉPONSES D'ERREUR:
❌ 401 Unauthorized : Email ou mot de passe incorrect
{
  "error": "Authentification échouée",
  "message": "Email ou mot de passe incorrect"
}

❌ 401 Unauthorized : Client sans mot de passe
{
  "error": "Authentification échouée",
  "message": "Ce client n'a pas de mot de passe configuré"
}

3. ROUTES D'AUTHENTIFICATION
================================================================================

ROUTES PUBLIQUES (pas de token requis):
---------------------------------------
POST /api/clients                  → Créer un client
POST /api/client/auth/login        → Se connecter

ROUTES PROTÉGÉES (token JWT requis):
------------------------------------
GET  /api/client/auth/me           → Informations du client connecté

Format du header pour routes protégées:
Authorization: Bearer <votre_token_jwt>

EXEMPLE - MES INFORMATIONS:
GET /api/client/auth/me
Headers: Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

RÉPONSE (200 OK):
{
  "id": 1,
  "email": "jean.dupont@example.com",
  "first_name": "Jean",
  "last_name": "Dupont",
  "phone_number": "+33612345678",
  "address": "123 Rue de la Paix, Paris",
  "birth_date": "1990-05-15",
  "gender": "M",
  "nationality": "Française"
}

4. ROUTES DES OPÉRATIONS BANCAIRES (Token JWT requis)
================================================================================

GESTION DES COMPTES:
-------------------
GET  /api/client/accounts              → Liste de tous mes comptes
GET  /api/client/accounts/{id}         → Détails d'un compte spécifique

OPÉRATIONS FINANCIÈRES:
-----------------------
POST /api/client/accounts/{id}/deposit    → Effectuer un dépôt
POST /api/client/accounts/{id}/withdraw   → Effectuer un retrait
POST /api/client/accounts/{id}/transfer   → Effectuer un virement

HISTORIQUE ET RELEVÉS:
---------------------
GET  /api/client/accounts/{id}/transactions  → Historique des transactions
GET  /api/client/accounts/{id}/statement     → Relevé bancaire

6. CORRECTION DU BUG ADMIN LOGIN (StackOverflowError)
================================================================================

PROBLÈME RENCONTRÉ:
Le login admin causait une erreur StackOverflowError due à une boucle
récursive dans AuthenticationManager.

SOLUTION APPLIQUÉE:
1. Modifié AuthService pour ne plus utiliser AuthenticationManager
2. Vérification directe du mot de passe avec passwordEncoder.matches()
3. Mise à jour de SecurityConfig pour autoriser les endpoints client

FICHIERS MODIFIÉS:
- AuthService.java : Suppression de l'injection AuthenticationManager
- SecurityConfig.java : Ajout routes publiques /api/client/auth/**
- SecurityConfig.java : Configuration du DaoAuthenticationProvider

MAINTENANT L'ADMIN PEUT SE CONNECTER VIA:
POST /api/auth/login
{
  "username": "admin",
  "password": "motdepasse"
}

7. CODES DE STATUT HTTP
================================================================================

200 OK              : Opération réussie
201 Created         : Client créé avec succès
400 Bad Request     : Données invalides ou manquantes
401 Unauthorized    : Authentification échouée ou token invalide
403 Forbidden       : Accès refusé (solde insuffisant, compte d'un autre)
409 Conflict        : Email déjà utilisé
500 Internal Error  : Erreur serveur

================================================================================
8. SÉCURITÉ
================================================================================

✅ Mots de passe encodés avec BCrypt (impossible à décoder)
✅ Tokens JWT signés avec clé secrète (durée 24h)
✅ Vérification que le client accède uniquement à SES comptes
✅ Protection contre les montants négatifs
✅ Vérification du solde avant retrait/virement
✅ Password jamais retourné dans les réponses JSON
✅ Claim "userType" dans le JWT pour distinguer CLIENT/ADMIN

11. RÉSUMÉ RAPIDE - WORKFLOW COMPLET
================================================================================

ÉTAPE 1: Créer un client
POST /api/clients avec toutes les informations + password

ÉTAPE 2: Se connecter
POST /api/client/auth/login avec email + password
→ Récupérer le access_token

ÉTAPE 3: Utiliser le token
Ajouter "Authorization: Bearer <token>" dans toutes les requêtes suivantes

ÉTAPE 4: Effectuer des opérations
- Voir comptes: GET /api/client/accounts
- Dépôt: POST /api/client/accounts/{id}/deposit
- Retrait: POST /api/client/accounts/{id}/withdraw
- Virement: POST /api/client/accounts/{id}/transfer
- Historique: GET /api/client/accounts/{id}/transactions
- Relevé: GET /api/client/accounts/{id}/statement
